# ADR-028 — shared read-only audio access component (2026-11-10)
- Status: Proposed. The owner approved the file-audio-analyzer design on 2026-11-10, including this shared component, its narrow dependency exception and the canonical import-path change; formal acceptance follows Codex review of the implementation. ADR-027 is unchanged.
- Decision: move artifact-location resolution and WAV integrity reading out of `adapters.rendering` into a separate shared adapter component, `autonomous_mixing.adapters.audio_io`, so that rendering and the forthcoming file-backed level analyzer use one read-only WAV policy without importing each other's internals.
  1. Ownership: `audio_io.locations` (`ResolvedArtifactLocation`, `LocationResolutionFailureCode`, `LocationResolutionError`, `resolve_artifact_location`) and `audio_io.integrity` (`CheckedAudio`, `IntegrityFailureCode`, `IntegrityError`, `check_wav_integrity`, `check_resolved_wav_integrity`, `WAV_CONTAINERS`) are the former rendering modules, moved with their private helpers and implementations unchanged. Each name has one definition; the old `adapters.rendering.locations` and `adapters.rendering.integrity` paths are removed without aliases or re-exports.
  2. New public record `audio_io.limits.AudioReadLimits(max_file_bytes, max_decoded_bytes)`: frozen, both fields required, each an exact built-in `int` of at least one (bool, float, int subclasses and NumPy integers rejected; no caps, defaults or conversion), checked file limit first with the reader's existing labels. The reader's private `_require_limit` moves unchanged into `limits` and is shared within the component only; other components consume `AudioReadLimits`.
  3. Dependency policy, an exception to ADR-027 rule (c) limited to exact module edges: `audio_io.locations` imports `core.records.artifacts` and the standard library; `audio_io.limits` the standard library; `audio_io.integrity` its own `locations` and `limits`, `core.records.artifacts`, the standard library, NumPy and soundfile. The only permitted external clients are `rendering.workspaces` (`locations`), `rendering.gain_mix` (`locations`, `integrity`), `rendering.state_integrity` (`locations`, `integrity`, `limits`) and `rendering.run_renderer` (`locations`). No other adapter or module may import the component, and no other component may import its private names. The component imports no consumer, other adapter, core loop or stage, driver or evaluation code, and its package initializer is docstring-only, so location resolution loads no NumPy or soundfile. The future analyzer edge is added with its implementation.
- Source: owner-approved design `2026-11-10-file-audio-analyzer-design.md` and the shared-audio-read plan (Codex project folder); ADR-023 (location resolution), ADR-027 rule (c).
- Rationale: the level analyzer must read the same WAV files with the same path, limit and decoding policy as rendering. Copying the reader would let the policies drift; letting the analyzer import rendering would make one consumer depend on another. A separate component with exact client edges keeps one implementation without opening adapters to arbitrary cross-imports.
- Consequences:
  - File access, validation order, errors and numerical behavior are unchanged; consumers and tests import the new canonical paths. `FileStateIntegrityInspector` validates its limits through `AudioReadLimits` at the same point and order as before. `ProcessingLimits` in `rendering.gain_mix` is unchanged.
  - Internal import paths change intentionally; no public core contract changes. `AnalysisRequest`, the analyzer, level kernels, provider and driver are not part of this decision.
  - Enforced by `tests/architecture/test_adapters.py` (exact client edges and the private-name check) and `tests/architecture/test_shared_audio_access.py` (edges, single ownership, removed paths, counterexamples and fresh-process isolation). No requirement status changes.
  - Update 2026-11-11 (implementation of the edge reserved in point 3; ADR still Proposed, decision unchanged): `dsp_analysis.file_analyzer` is now a permitted client of `locations`, `integrity` and `limits` (public names only); no other `dsp_analysis` module may import the component. Enforced by the same two test files.
