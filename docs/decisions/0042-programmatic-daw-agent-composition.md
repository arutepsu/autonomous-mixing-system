# ADR-042 — Owned programmatic DAW agent composition (2026-11-24)

- Status: Proposed; R5B implementation reviewed for the 2026-11-24 checkpoint. CLI activation remains separate.
- Source: owner authorization to continue the R5B increment of the [agent-composition plan](../superpowers/plans/2026-11-23-r5-agent-composition.md).
- Decision: one driver context, `DawAgentRuntime`, owns preparation, analyzers/router, experimental diagnosis, audited Claude adapter, decision-evidence verifier, durable run store, integrity inspector, FL controller/journal and the existing export handoff. It calls existing `run_daw` and `resume_daw`; no second coordinator, generic dependency registry or adapter is introduced.
- Decision: creation takes an explicit preparation request, provider configuration, separately supplied credential and a typed request factory. The factory consumes the verified measurement plan and its diagnosis definitions, returning producer roles, permissions, criteria and budgets as an existing `RunRequest`. The runtime refuses a changed start/run identity, missing exact diagnosis definitions or an incoming provider binding. It invents no musical target or acceptance threshold. The JSON operator schema and CLI activation remain R5C.
- Decision: `DawAgentBinding` is an additive subtype of the existing `ProviderRunBinding`. Its canonical local settings freeze roots, stores/session/MIDI configuration, read/evidence/audit limits and documented alignment methods. Existing base record field sets are unchanged; the additive codec tag needs no run schema change (schema2) or exchange schema change (schema1). Credentials are never stored. Local operational paths do not enter the public Situation or provider packet. Public producer/diagnosis prose retains the existing public-content responsibility; this is not general secret sanitization.
- Decision: artifacts live in a fresh `<run-id>.runtime` directory beside the existing `<run-id>.sqlite` store. Plans, evidence and audit have distinct owned locations; audit files are outside the top-level run-store scan. Existing paths refuse rather than overwrite. Failed creation closes acquired resources in reverse order and leaves diagnostic artifacts, never deletes originals or silently retries preparation.
- Decision: native baseline encoding and affected-artifact render specification, sample rate, timeline start and frame count must match the explicit export session before external transport construction. The profile remains the exact reviewed calibrated FL profile. Preparation validates supported P1 ingress; every candidate still passes the real analyzer, so nonidentical stereo is unavailable and never silently averaged.
- Decision: reopening loads the exact stored request and local binding, compares current operator/provider/prompt/schema settings, loads the frozen manifest without preparing again, verifies recorded evidence and uses existing restart classification. Only a recorded suspension resumes; no recorded write is resent. The export inventory resolves each current accepted checkpoint and its current protected files, including intermediate accepted edits.
- Resource lifetime: use as a context manager or call `close`. Stores and provider transport close on failed construction and normal close; MIDI transports retain the controller's existing per-exchange ownership. A closed runtime refuses effects. Transport factories must construct only and must not dispatch themselves. Only external transport, clock and identity seams are injectable; diagnosis, measurement, admission, verification and acceptance are concrete implementations.
- Evidence: integration tests use actual numerical WAVs and internal software, with labelled provider replies and simulated FL device transport. They exercise abstention, provider failures, rejection/feedback/recovery, restart, lost apply reply, lost acceptance acknowledgement and intermediate acceptance. They establish engineering composition, not model quality, physical FL behavior or musical improvement.
- Consequences: the caller must explicitly configure legitimate current inputs and acceptance conditions. Three separate stores/files do not form an atomic transaction; existing fail-closed provenance and restart rules remain essential. File checks are not race-free and no power-loss guarantee is added. Creation that fails after reserving its private directory is intentionally not automatically reusable.
- Scope: experimental thresholds unchanged and uncalibrated; qualified masking, P2/P3, CLI start/continue, live provider/FL runs, saves, exports and installation are outside this increment. No requirement status or accepted ADR changes.
- Supersedes: no accepted ADR. Extends proposed ADR-041 and the existing driver responsibilities.

## Review correction (2026-11-24)

The fresh read-only review reproduced missing early native-export metadata checks. Four regressions (frame count, start, rate and render spec) failed before the fix. Creation now rejects them before external construction rather than spending provider calls and later reporting insufficient evidence. Existing action-level preflight remains independently enforced.
