# ADR-024 — fresh output workspace allocation in a separate infrastructure component (2026-11-02)
- Status: Proposed; awaiting owner review of the implementing stage.
- Decision: turn an application-issued `ExecutionWorkspace` into exactly one fresh, empty directory below an explicit output root, created exclusively, after mandatory protected-location checks; retain the directory after any later failure and never clean up.
  1. Separate component with a narrow application dependency: `autonomous_mixing.infrastructure.workspaces` (initializer re-exporting `allocation` only) exports exactly `WorkspaceRoot`, `WorkspaceAllocationRequest`, `AllocatedWorkspace`, `WorkspaceAllocationFailureCode` (`ROOT_KEY_MISMATCH`, `INVALID_INVENTORY`, `INVALID_ROOT`, `UNSUPPORTED_PATH`, `PROTECTED_LOCATION`, `PROTECTED_OVERLAP`, `COLLISION`, `NOT_WRITABLE`, `WORKSPACE_CHANGED`), `WorkspaceAllocationError(code, message, *, created_directory=None)` (`ValueError` subclass) and `allocate_workspace(request)`. `allocation` imports only the standard library and the `domain.project`, `application.execution` and `infrastructure.filesystem` public interfaces. This is the first narrowly scoped infrastructure-to-application dependency, because it realizes the application-owned `ExecutionWorkspace`; the domain and application still never import infrastructure, and importing `audio` or `filesystem` loads neither `workspaces` nor the application. This extends the source rules of ADR-022 and ADR-023.
  2. Explicit root and token: `workspace.root_key` must equal `WorkspaceRoot.root_key` exactly; no root registry or current-directory fallback. The root must already exist as a directory and use the same supported native absolute syntax as the input resolver; it is strictly resolved (aliases allowed and recorded). `directory_token` is used unchanged as the sole child name; its ASCII pattern is rechecked, and on Windows reserved device names are rejected (`PureWindowsPath.is_reserved()`, Python 3.11).
  3. Mandatory current-state inventory plus caller-supplied history: `protected_locations` must cover, with exactly equal metadata, the union of `state.audio.artifacts` and every track-gain `input_artifact`. Additional history and cross-project entries are caller supplied, receive the same checks, and are not proven exhaustive. Every entry is freshly re-resolved through the filesystem interface, compared exactly with its record and required to be a regular file; no content is opened. A protected canonical path that equals, lies below or lies above the planned child is rejected (`PROTECTED_OVERLAP`, via `PurePath.is_relative_to`).
  4. Fresh exclusive child: one `mkdir(parents=False, exist_ok=False)`. Any existing child, whether file, directory, symlink, dangling link or junction, is a `COLLISION` and is left untouched: no reuse, suffix generation or retry.
  5. Post-creation checks and retained failures: the root and child are re-resolved, the root must be unchanged and still a directory, the child must be the exact direct child, a real directory (not a symlink or reparse point) and empty. Expected failures after creation raise `WORKSPACE_CHANGED` with `created_directory` set; the directory is retained, and nothing is deleted, renamed or cleaned up. Failure mapping is narrow; unrelated `OSError`, `MemoryError` and programming errors propagate.
  6. Unchanged guarantees: the resolver, both verifier entry points and the DSP kernels keep their behavior and exports (`filesystem` 4, `audio` 7).
- Source: owner-approved design "Fresh output workspace allocation" and its implementation plan (2026-11-02), kept in the owner's planning workspace; audit finding F4; open question on output workspace allocation in `docs/architecture/overview.md`.
- Rationale: `ExecutionWorkspace` is a logical assignment; a later writer needs a physical location whose creation by this call is observable, that cannot silently reuse earlier outputs, and that does not overlap known protected files. Exclusive creation gives clear collision semantics without ownership markers. Consuming the full `ProjectState` (rather than a `ProcessingPlan`, which omits the current mix's location and other protected artifacts) makes the current-state minimum checkable. Rejected alternative: reusing checked existing directories, which needs persistent ownership, recovery and cleanup machinery that does not exist. Generating replacement tokens or retrying collisions was also rejected, because the caller must choose a new logical assignment explicitly.
- Consequences:
  - Failed attempts leave directories behind; a retry with the same token is a collision. Recovery and cleanup are separate future policies.
  - `AllocatedWorkspace` can be built manually or be stale; it is not proof of allocation, ownership, permission to write or a security capability.
  - The checks describe the filesystem observed during the calls: no complete historical inventory, durable ownership, execution lock, race-free protection or confinement, or protection against later writers follows. Concurrent allocation of one assignment yields one directory and one collision; this is exclusive name creation, not a lock.
  - Overlap uses `is_relative_to`, which is case-insensitive on Windows; per-directory case sensitivity is not accounted for.
  - F4 is reduced, not closed; F2 is unaffected. No WAV writing, processing adapter or connected execution pipeline is added; no requirement is completed or changes status; no perceptual or research-performance result follows.
  - Open questions: a project-history and retention registry; durable ownership and cleanup; execution locks; the writer's no-overwrite protocol.
