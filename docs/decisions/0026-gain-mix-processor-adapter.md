# ADR-026 — gain/full-mix processor adapter bound to a pre-allocated workspace (2026-11-03)
- Status: Proposed; awaiting owner review of the implementing stage.
- Decision: implement the first `AudioProcessor` (ADR-020 §5) as a separate infrastructure component that composes the existing verifier, numerical kernels and exclusive WAV writer, bound per execution to a workspace allocated by the caller.
  1. Separate component: `autonomous_mixing.infrastructure.processing` (initializer re-exporting `gain_mix` only) exports exactly `GAIN_MIX_PROCESSOR`, `ProcessingLimits` and `GainMixProcessor`. Nothing imports it yet.
  2. Binding (D1): `GainMixProcessor(workspace: AllocatedWorkspace, limits: ProcessingLimits)`. Allocation stays with the caller, which holds the state and the protected-location inventory. The plan's inputs are looked up in `workspace.request.protected_locations` by `(project_id, artifact_id)`, and each record's artifact must equal the plan's record. The port and `ProcessingPlan` are unchanged.
  3. Order of `process(plan)`; the first failure wins:
     1. wiring checks without file access: the plan type; `plan.workspace` equals the bound assignment; the bound state's snapshot has the plan's project and before revision; inputs match the render settings, frame count and timeline start (normally guaranteed by preflight); input location lookup;
     2. verification of the fixed target input, then of each non-target current stem in recipe order, through `verify_resolved_wav_artifact`; the obsolete current target stem and the current mix are never opened;
     3. `apply_absolute_gain` on the fixed input, then `sum_stems` in recipe order with the new target in place of the obsolete one;
     4. `write_wav_output` of `target.wav`, then `mix.wav`;
     5. output records and evidence.
  4. Failure classification (D2): wiring errors raise plain `ValueError` before any file access. Expected failures return `ProcessingFailure(FAILED, ...)` with code `input_verification_failed` (verifier or resolution error), `processing_failed` (unrepresentable kernel result) or `output_failed:<writer code>`; the message names every retained file. Unexpected exceptions propagate unchanged, and the caller records the outcome as uncertain. The processor never returns `UNCERTAIN`.
  5. Outputs (D3): fixed filenames `target.wav` and `mix.wav`. `AudioArtifact.location` is `"<directory_token>/<filename>"`, relative to the output root, so a later execution can resolve an output as an input. `content_hash` is the writer's readback SHA-256; dimensions come from the written file, the timeline start from the fixed input and `render_spec` from `plan.render_spec.ref`.
  6. Evidence and identity (D4): the target cites the fixed input; the mix cites the new target followed by the non-target stems in recipe order. Both claim verified inputs and finite samples, record `peak_linear = max|samples|`, the plan's `ProcessingSpec` and the module constant `GAIN_MIX_PROCESSOR = VersionRef("autonomous_mixing.gain_mix_processor", "1")`, which callers cannot configure. The processor does not call `validate_processed_candidate`; the caller does, as the port specifies.
  7. Limits (D5): `ProcessingLimits(max_file_bytes, max_decoded_bytes)`, both required positive built-in `int`s with no defaults, passed unchanged to every verification and both writes.
  8. Import rule (extends ADR-022): `gain_mix` may import the standard library, NumPy, the `domain.project`, `domain.shared` and `domain.action` interfaces, the `application.execution` interface and the `audio`, `filesystem`, `workspaces` and `wav_output` interfaces only. It is the second infrastructure→application dependency after `workspaces.allocation`, scoped to the port's own package, and the only module importing `wav_output`.
- Source: owner-approved design "Gain/full-mix processor adapter" (`docs/architecture/gain-mix-processor-design.md`, decisions D1–D5 as recommended, approved 2026-11-03); ADR-020 §5; audit findings F3 and F4.
- Rationale: every building block existed and was tested; the port had no implementation, so no candidate audio could be produced (FR-17). Binding a pre-allocated workspace keeps the application contracts and the ADR-022 layer rule intact, and reusing the allocation inventory means input locations need no second, possibly diverging mapping. Verifying every input before the first write means input and kernel failures leave no output files.
- Consequences:
  - Contributes to FR-08, FR-17, QR-01, QR-02 and OP-02; none is met, and no requirement status changes.
  - F3 narrowed: adapter evidence is now produced, with a fixed processor identity; environment provenance (Python and library versions) remains open and belongs to the run record (QR-03). F4 narrowed: the executor writes only through the exclusive writer into a workspace allocated with protected-overlap checks; complete history inventory, parent pinning, race-free confinement and locks remain missing. F2 is unaffected.
  - Input bytes are verified at capture time only. Output hashes are not reproducible across runs (PEAK chunk, ADR-025), though samples are.
  - There is no two-output transaction: a mix-write failure leaves a verified `target.wav`. Nothing is cleaned up.
  - Peak memory grows with the number of stems held at once and is not bounded by the limits.
  - No execution service, receipt or candidate-state assembly is added; a connected loop still needs that service, M1 detection and the M3 decision adapter. No perceptual or research-performance result follows.
